Project: [ClearIntel public website](https://clearintel-public.onrender.com/) · GitHub repository: `v5k2s9dry5-hue/ClearIntel-Public-Website`.

This is the **public, lawful public-source product**, separate from the private Ubuntu/WSL investigation engine. Roadmap items are plans, not promises of real-time/complete coverage or independently verified events.

## 23 November — feed availability and snapshot health

- Treat an all-provider outage as **unavailable**, not an ordinary empty search. Public search notices and the feed-coverage control explain when zero providers responded, when coverage was partial, when no providers were checked, or when all configured checks responded.
- Country briefings show source-check state and the UTC timestamp of the latest available snapshot. On a failed refresh that retains prior headlines, the source-health control says the counts and timestamp belong to the **previous** snapshot.
- Keep the default interface compact, the detailed list expandable and mobile touch targets at least 44px. Preserve source-specific error categories without displaying exception messages or secret configuration.
- This is **per-request source-health reporting**, not background provider telemetry, historic provider uptime, or proof that publisher content is fresh. Long-term last-success metrics, optional alerts and cross-source reliability analysis remain planned.
- No new provider polling, additional infrastructure, location tracking or fees. Require Python and desktop/mobile Chromium checks before release.

### Analysis, monitoring, briefings and interface backlog

1. **Source-health monitor:** per-source last successful check, last provider observation, current unavailable/rate-limited state, and what a missing response does *not* establish. No extra polling just to make indicators look live.
2. **Cross-source correlation:** cluster related reports by source URL and wording; detect possible syndication, distinguish independent reporting from duplicated text, preserve conflicting accounts and label confidence as an assessment, not truth.
3. **Country intelligence briefings:** user-generated country snapshots with citations, UTC timestamps, source coverage and clear separation between reported facts, uncertainties and assessment; export to PDF, initially in browser.
4. **Historical playback:** extend browser-local Intelligence Replay into a bounded country/topic timeline only from observations actually captured, then consider public dated archive sources where provenance is preserved. Never fabricate past snapshots.
5. **AI research assistant:** optional, human-verifiable, citation-first help for finding and summarising public sources only; defer until cost, privacy, quality and prompt-injection safeguards are acceptable. No autonomous judgments of truth.
6. **Alerts and notifications:** opt-in alerts for future source updates or thresholds, with deduplication, quotas, consent, retention and cost review before deployment. Not implemented.
7. **Better reporting tools:** evidence selection, a source audit trail, explicit observed/published/event timestamps, downloadable source-cited reports and locally stored notes without leaking private investigation files.
8. **Expanded category controls:** separate geopolitical, maritime, aviation, disaster, cyber, economic, travel and civil-unrest layers when evidence sources exist; distinguish categories from source confidence and incident severity.
9. **Accessibility and usability:** easy default mode, optional analyst details, helpful hover/focus explanations on desktop, tap-friendly mobile disclosures, swipe navigation and no inaccessible tooltip overlays.

**Implementation sequence:** (A) reliability/UX/SEO/deployment checks; (B) UKMTO source and permission evaluation plus source health; (C) add a small set of robust, permitted official feeds; (D) source correlation and briefing exports; (E) historical playback; (F) assistant and opt-in alert infrastructure only if justified. Each addition requires desktop/mobile regression tests, failure handling and the existing public/private security boundary.

## NEW flagship: Intelligence Replay (approved for roadmap 22 November)

**Goal:** Let a researcher reconstruct the *observed evolution of a developing story* across public-source reports, rather than just read the most recent headline.

### Replay R0 — £0 browser-local prototype (after current reliability work)

- Add a user-initiated **Save snapshot** action for public news results. Keep a bounded history for the current browser, without accounts, server storage or background data collection.
- Snapshots record **observed-at UTC**, search term and time window, original linked headline, publisher, provider, and supplied feed/first-seen timestamp. An observed-at time is **not** the event occurrence time.
- Offer a replay control to view only **actually saved** snapshots; explain when no earlier snapshot exists. Never fabricate back history or quietly substitute current results for historical results.
- Explicitly label all results as unverified reporting leads. Separate observation time, publication time and reported event time where available.
- Include a local **Clear history** control and document how long browser data persists. Use bounded quotas and conservative content lengths, avoid personal data storage, and ensure no snapshots sync to the server.
- Desktop/mobile and accessibility tests, including empty history, repeated identical snapshots, browser-storage denial and deletion.

### Replay R1 — source evolution (basic saved-result comparison implemented; advanced analysis planned)

- Basic comparison now identifies newly present, no longer present and updated headline/publisher text at the same source URL **between saved observations**. These are limited differences in saved result sets, not evidence of publication/deletion or incident status.
- **Exact normalized headline wording groups implemented:** group saved titles that differ only by case, spacing or punctuation, and display their original links and listed publishers. A match is not evidence of independence or syndication. Broader similarity, syndication provenance and source attribution remain future work.
- Surface source corrections or contradictions as **potential** differences needing human review; preserve links and timestamps.

### Replay R2 — richer intelligence and exports (later phase)

- Bounded timeline filtered by country or topic; optionally compare periods and export replay history with source citations and caveats.
- Only consider server-side long-term retention with clear user consent, privacy review, abuse controls, lawful processing, capacity planning and an explicit cost decision.
- Do not ingest historical stories from elsewhere and present them as having been observed by ClearIntel at an earlier time.

### Acceptance criteria

- A replay only includes snapshots saved after the feature was enabled and actually captured.
- A user can distinguish `observed_at_utc`, `feed_time_utc` and `incident_time_utc` at every relevant view.
- Source and comparison errors do not erase previously saved valid snapshots.
- Browser-local replay works without paid API services or exposure of private ClearIntel investigations.
- All historical claims are backed by retained source references; the feature never asserts that a publication proves an incident.
